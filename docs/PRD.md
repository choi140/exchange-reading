# 낯선 밑줄 — 익명 교환독서·교환일기 웹앱 PRD

> 원본: [Claude Doc](https://claude.ai/artifact/CzzFGXDqp23qeduMBbtov1) · 2026-11-01 · 세연
>
> **마감 버전.** 11월 2일(월) 자정까지 혼자 바이브코딩으로, 웹에 배포돼 실제로 쓸 수 있는 상태까지 만드는 것이 목표다. 작업 시간 약 13시간으로 끝날 범위만 담았고, 나머지는 11장 '나중에 할 것'으로 미룬다.

## 1. 개요

**낯선 밑줄**은 모르는 사람과 전자책 한 권, 일기장 한 권을 천천히 주고받는 익명 슬로우 소셜 웹앱이다. 친구끼리 하던 교환독서를 낯선 사람과의 경험으로 바꾸는 것이 핵심이다.

**배경.** 교환독서는 한 권의 책을 돌려 읽으며 밑줄과 메모를 남기는 방식으로, 2025년부터 20대 사이에서 빠르게 퍼졌다. SNS 후기 게시물이 수십만~백만 회대 조회수를 기록했고, 창비·현대문학 같은 출판사도 교환독서 프로그램을 운영했다. 현대문학은 온라인으로 모르는 상대를 매칭하는 프로그램까지 시도했다.

**문제.**
- 아는 사람끼리는 생각이 닮아 있어서, 같은 책을 읽어도 시각이 비슷하게 모인다.
- 아는 사람에게 속마음을 보이는 건 부끄럽다. 메모나 일기에 솔직하게 쓰기 어렵다.
- 실물 교환독서는 만나거나 택배를 보내야 해서 번거롭고, 같이 할 사람이 있어야 시작할 수 있다.

**기회.** 익명의 낯선 사람과 매칭하면 다른 시각을 만나고, 더 솔직하게 쓸 수 있다. 같은 구조를 일기에 적용하면 남의 일상을 들여다보거나, 대나무숲처럼 내 이야기를 털어놓는 공간이 된다.

**완료 기준 (브라우저 창 2~3개로 직접 확인)**

- [ ] 함께 읽기: 낯선 사람과 같은 책 방에 배정되고 펜 색이 생긴다
- [ ] 함께 읽기: 문단에 메모를 남기면 다른 사람 메모가 열리고, 답글을 달 수 있다

- [ ] 교환일기: 짝을 찾고 번갈아 일기를 쓸 수 있다

**이번에 하지 않는 것:** 로그인 화면, 안전장치, 순서대로 넘기는 릴레이, 기한·자동 처리, 알림, 취향 매칭, 대나무숲. 목록은 11장.

## 4. 핵심 기능 (마감 버전)

책과 일기 모두 **혼자 / 함께** 두 가지 모드가 있다. 혼자 모드는 함께 모드의 화면을 그대로 쓰고 상대만 없애서, 추가 작업이 적다.

### 4.1 책 읽기

책을 고르면 "혼자 읽기"와 "함께 읽기" 버튼이 나온다.

| 기능 | 혼자 읽기 | 함께 읽기 (책 방) |
|---|---|---|
| 방 | 나만 있는 방이 만들어진다 | 같은 책의 빈자리 있는 방(최대 3명)에 들어간다. 없으면 새 방 |
| 펜 색 | 고정 (검정 펜) | 남은 색 중 하나 (파란 펜, 초록 펜, 주황 펜) |
| 리더 | 본문을 문단 단위로 보여주고, 문단 옆에 메모 개수 표시 | 같음 |
| 메모 | 문단을 눌러 메모 (300자 이내). 나만 본다 | 같은 방 사람들이 펜 색별로 본다 |
| 블라인드 | 없음 | 그 문단에 내 메모가 없으면 "숨겨진 메모 2개"로만 보인다. 내가 쓰거나 "그냥 보기"를 누르면 열린다 |
| 답글 | 없음 | 메모 아래 한 단계 답글 |

문장 드래그 하이라이트는 나중에 넣는다.

### 4.2 일기 쓰기

"새 일기장"을 누르면 "혼자 쓰기"와 "교환일기" 중 하나를 고른다.

| 기능 | 혼자 쓰기 | 교환일기 |
|---|---|---|
| 시작 | 바로 내 일기장이 생긴다 | 기다리는 사람이 있으면 바로 짝. 없으면 "짝을 기다리는 중" |
| 쓰기 | 언제든 쓸 수 있다 | 마지막 일기가 내 글이면 잠기고 "짝의 답장을 기다리는 중" |
| 오늘의 질문 | 쓰기 창 위에 표시 (코드에 넣은 10개를 날짜로 순환) | 같음 |
| 분량 | 한 편 1,000자 이내 | 같음 |

### 4.3 홈

책 목록, 내 책(혼자·함께), 내 일기장(혼자·교환)을 한 화면에 보여준다. 교환일기가 내 차례면 "내 차례" 표시를 붙인다. 알림은 이 표시로 대신한다.

### 4.4 로그인 없이 사람 구분하기

로그인 화면은 없다. 처음 접속하면 Supabase가 화면 뒤에서 익명 계정을 만들고 그 브라우저에 기억한다. 낯선 사람과 방을 나누려면 "누가 누구인지"는 구분돼야 하기 때문이다. 단, 브라우저를 바꾸거나 방문 기록을 지우면 내 책·일기에 다시 들어갈 수 없다.

## 6. 안전장치

마감 버전에서는 뺀다. 모르는 사람에게 주소를 공개하기 전에는 연락처 자동 가림, 신고·차단, 위기 표현 안내, 연령 확인을 다시 넣는다 (11장).

## 7. 책 데이터

저작권이 끝난 단편 3편만 넣는다. 단편이라 챕터 없이 문단 배열 하나로 충분하다.

| 작품 | 저자 (사망) |
|---|---|
| 운수 좋은 날 | 현진건 (1943) |
| 봄·봄 | 김유정 (1937) |
| 메밀꽃 필 무렵 | 이효석 (1942) |

- 한국은 저자 사후 70년까지 보호하고, 1962년 이전에 사망한 저자의 작품은 대체로 만료되었다.
- 본문은 한국저작권위원회 공유마당이나 위키문헌처럼 출처가 분명한 곳에서 가져오고, books 테이블의 source 칸에 출처를 적는다. 현대어로 고친 판본은 편집자 권리가 있을 수 있으니 이용 조건을 확인한다.
- 작업: 본문을 복사해 빈 줄 기준으로 문단을 나눠 JSON으로 만든다. 약 30분.

## 8. 작업 일정

총 작업 약 13시간. 가장 중요한 규칙은 **1단계에서 바로 배포하고, 매 단계가 끝날 때마다 다시 배포하는 것**이다. 그러면 어느 시점에 멈춰도 웹은 돌아간다.

1. **준비 (1시간)**: GitHub, Vercel, Supabase 계정 만들기. 바이브코딩 도구 정하기. 책 본문 JSON 만들기 (7장).
2. **뼈대 + 익명 계정 + 첫 배포 (1.5시간)**: 접속하면 자동으로 익명 계정이 생기고 빈 홈이 Vercel 주소에서 열리면 끝.
3. **DB + 책 데이터 (1.5시간)**: 테이블 만들고 단편 3편 넣기. 홈에 책 목록.
4. **혼자 읽기 + 리더 + 메모 (2.5시간)**: 혼자 방을 먼저 완성한다. 여기까지만 해도 쓸 수 있는 앱이다.
5. **혼자 일기 (1시간)**: 일기장, 오늘의 질문, 쓰기.
6. **함께 읽기 (2시간)**: 방 배정, 펜 색, 블라인드, 답글.
7. **교환일기 (2시간)**: 짝 찾기, 교대 작성, 홈의 "내 차례".
8. **다듬기 + 테스트 (1.5시간)**: 브라우저 창 3개로 2장 완료 기준을 하나씩 확인, 휴대폰 화면 점검, 최종 배포.

**혼자 모드를 먼저 만드는 이유:** 함께 모드는 혼자 모드 화면에 상대를 더하는 것이라, 순서가 자연스럽고 중간에 멈춰도 작동하는 앱이 남는다.

**시간이 모자라면 이 순서로 자른다:** 답글 → 블라인드 → 교환일기 → 함께 읽기. 배포는 자르지 않는다.

## 9. 기술 설계

Next.js + Supabase + Vercel. 서버를 따로 만들지 않고, 계정·DB·권한을 모두 Supabase에 맡긴다.

**스택**

| 영역 | 선택 |
|---|---|
| 화면 | Next.js (App Router) + TypeScript + Tailwind CSS |
| 사용자 구분 | Supabase 익명 로그인 (Authentication 설정에서 Anonymous Sign-Ins 켜기). 접속 시 세션이 없으면 자동으로 `signInAnonymously()` |
| DB·권한 | Supabase Postgres + RLS |
| 배포 | Vercel (GitHub 연결, push하면 자동 배포) |

**테이블**

| 테이블 | 컬럼 |
|---|---|
| books | id, title, author, source, paragraphs (text 배열) |
| rooms | id, book_id, mode (solo / together), created_at |
| room_members | room_id, user_id, pen_color, alias |
| notes | id, room_id, user_id, paragraph_index, parent_id (답글이면 원 메모 id), body, created_at |
| unlocks | room_id, user_id, paragraph_index ("그냥 보기" 기록) |
| diaries | id, mode (solo / exchange), status (waiting / active), created_at |
| diary_members | diary_id, user_id, alias, pen_color |
| diary_entries | id, diary_id, user_id, prompt, body, created_at |

혼자 모드는 멤버가 나 하나인 방·일기장일 뿐이라, 테이블과 화면을 함께 모드와 같이 쓴다. 화면은 mode를 보고 블라인드·답글·차례 잠금만 켜거나 끈다.

**DB 함수 세 개.** `start_solo_room(book_id)`는 내 혼자 방을 돌려주거나 만든다. `join_room(book_id)`는 빈자리 있는 함께 읽기 방을 찾거나 만들고 남은 펜 색을 준다. `find_diary_partner()`는 waiting 상태인 교환일기장에 들어가거나 새로 만든다. 혼자 일기장은 함수 없이 바로 만든다.

**권한(RLS).** 메모는 같은 방 멤버만, 일기는 같은 일기장 멤버만 읽고 쓸 수 있다. 혼자 모드는 멤버가 나뿐이라 이 규칙만으로 나만 보게 된다. 블라인드는 막히면 화면에서만 가리고 나중에 RLS로 옮긴다.

**화면**

| 화면 | 경로 |
|---|---|
| 홈 (책 목록, 내 책, 내 일기장) | `/` |
| 책 리더 (혼자·함께 공통) | `/room/[id]` |
| 일기장 (혼자·교환 공통) | `/diary/[id]` |

## 10. 바이브코딩 프롬프트

8장 일정의 단계마다 하나씩 넣는다. (단계별 프롬프트 전문은 원본 문서 참고)

**팁.** 단계가 끝날 때마다 git에 커밋하고 push해서 배포를 확인한다. AI가 망가뜨리면 직전 커밋으로 되돌리면 된다. 익명 계정은 브라우저마다 따로 생기므로, 일반 창·시크릿 창·다른 브라우저를 동시에 열면 낯선 사람 3명을 흉내 낼 수 있다.

## 11. 마감 리스크와 나중에 할 것

가장 큰 리스크는 시간이다. 배포를 맨 앞에 두고, 안 되는 건 8장 순서대로 자른다.

| 리스크 | 대응 |
|---|---|
| 한 단계에서 1시간 넘게 막힘 | 그 기능을 더 단순하게 바꾸거나 자르고 다음 단계로 |
| RLS 때문에 데이터가 안 보임 | 에러 메시지를 그대로 AI에게 붙여넣기. 정책을 하나씩 켜며 확인 |
| Vercel 배포 실패 | 환경변수(Supabase URL·anon key) 누락이 가장 흔하다. 빌드 로그를 AI에게 보여주기 |
| 혼자서는 매칭을 테스트하기 어려움 | 일반 창·시크릿 창·다른 브라우저가 각각 다른 익명 사용자가 된다 |
